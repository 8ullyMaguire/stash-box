# #778 — performer aliases joined into one string

**Status: not reproducible — the reported API does not exist. No production
change was made; behaviour is pinned by tests.**

## The report

The scraper returns performer aliases; Stash Box joins them into a single
comma-separated string instead of returning a list, so aliases containing commas
are ambiguous.

## What the investigation found

There is no scrape mutation anywhere in the GraphQL schema — the premise of the
report does not exist on this tree. The schema already exposes performer aliases
as `[String!]!`:

```graphql
aliases: [String!]!
```

so a list is returned and an alias containing a comma is one element rather than
two.

## What was done instead

`internal/api/performer_alias_comma_integration_test.go` pins the contract: an
alias containing a comma round-trips as a single list element. The test was
added to the existing `graphqlClient_test.go` output type so the real handler
path is exercised rather than a constructed model.

## Verification

```bash
grep -n "aliases" graphql/schema/types/performer.graphql   # [String!]!
export POSTGRES_DB="postgres:[REDACTED]@127.0.0.1:5434/stash-box-test?sslmode=disable"
go test -tags=integration -count=1 -run TestPerformerAlias ./internal/api/
```
