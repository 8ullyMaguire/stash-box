# #525 — deleted images break the edit forms

**Status: not reproducible — already fixed upstream. No code change was made,
and the candidate tests were deleted.**

## The report

Adding an image via the editor and then deleting it breaks the edit forms.

## What the investigation found

`imageList` in `internal/api/loaders.go` filters nil values out of the dataloader
result. `git log -S` dates that filter to commit `ea06fbf` (2025-11-16) — after
the October 2022 report — so the behaviour described has not existed on this tree
for a long time.

## Why no test was kept

Two candidate tests were written and both passed. So were they re-run with the nil
filter removed? Yes — and **they still passed**, because the SQL inner joins drop
deleted images before the dataloader ever sees them. A test that survives the
mutation of the code it claims to cover is not evidence of anything, and keeping
it would have put a false guarantee into the suite.

Both tests were deleted rather than committed.

## Verification for a future implementer

```bash
# The filter is in place:
grep -n "image == nil" internal/api/loaders.go

# And the joins that make a nil impossible:
grep -n "NOT deleted" internal/queries/sql/image.sql
```

If a future change removes the dataloader filter, a test for this becomes
writable — the joins must be bypassed first, or the fixture has to insert a row
that the query genuinely returns with no image.
