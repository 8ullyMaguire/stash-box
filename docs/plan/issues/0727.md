# #727 — a field reported as dead is live

**Status: not reproducible. No code change.**

## The report

A field was reported as unused / removable.

## What the investigation found

`url` is a live field the client depends on: it is returned by the scene and
performer queries, is used to build outbound links, and is exercised by
existing integration tests. Treating it as dead would have broken the client.

No code was changed, because the correct action is to do nothing.

## Verification for a future implementer

Before removing any apparently-unused GraphQL field:

```bash
# 1. Is it in the schema?
grep -rn "<field>" graphql/schema/types/
# 2. Does the frontend read it?
grep -rn "<field>" frontend/src/ --include=*.tsx --include=*.ts --include=*.gql
# 3. Does the Go code populate it?
grep -rn "<field>" internal/models/ internal/converter/
```

All three must agree before a field is safe to remove. A field referenced by
the frontend but not by Go is the dangerous case: it compiles, and it is always
empty at runtime.
